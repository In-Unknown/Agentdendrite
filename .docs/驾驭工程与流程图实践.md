# 任务：前端自动化测试与修复循环 SOP (v1.0)

## 角色池
- @测试审计员 (无记忆，仅看 TESTING_PLAN.md 和 TEST_REPORT.md)
- @MCP架构师 (负责方案制定与审查，输出 code_fix_Plan.md)
- @文件助手 (负责具体文件修改)
- @Git助手 (负责暂存与生成 .patch)
- @命令执行器 (负责 npm run build)

## 执行流程 (严格按照以下状态机执行，必须用 Mermaid 记录当前进度到 todo.md)

### State 1: 测试阶段
1. 循环调用 [@测试审计员] 执行测试。
2. 断点检查：如果测试中断或未发送"完成测试"信号，重新调用并让其读取历史文档继续。
3. 成功条件：生成完整的 `TEST_REPORT.md`。
4. 下一步：触发工具 `askuserquestion-mcp`，询问用户测试结果及是否修复。等待用户指令。

### State 2: 方案制定与修改
1. 用户确认修复后，调用 [@MCP架构师] 读取报错，输出修复计划至 `code_fix_Plan.md`。
2. 循环检查：再次调用 [@MCP架构师] 确认文档足够细致。
3. 执行修改：调用 [@文件助手] 根据计划修改文件。

### State 3: Diff 校验循环 (Inner Loop)
1. 调用 [@Git助手] 生成 `fixplan.patch`。
2. 调用 [@MCP架构师] 校验 patch 是否符合计划。
   - IF 不符合: 覆写问题到 `temp-fix.md` -> [@文件助手] 再次修改 -> [@Git助手] 更新 patch -> 回到步骤 2。
   - IF 符合: 进入 State 4。

### State 4: 编译校验循环 (Outer Loop)
1. 调用 [@Git助手] 暂存全部，生成 `staged.patch`。
2. 调用 [@命令执行器] 执行 `npm run build`。
   - IF 报错: 记录到 `error.md` -> 呼叫 [@MCP架构师] 出具 `fix_error.md` -> [@文件助手] 修复 -> 回到步骤 1。
   - IF 成功: 进入 State 5。

### State 5: 收尾与重启
1. 阻塞询问：用 `ask_text_question` 汇报并等待用户确认 MCP 工具状态。
2. 清理：删除除 `TESTING_PLAN.md` 外的所有中途生成的 md/patch 文件。
3. 重启：回到 State 1 重新测试，直到无 bug 为止。

## 严格限制
- 每次 Git 助手只暂存代码，绝对不能暂存 md 文件。
- 执行前，请先在 todo.md 中生成包含上述逻辑的 Mermaid 流程图，并严格跟踪执行进度。
